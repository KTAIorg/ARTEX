# 价值矩阵调度

> 授权渗透测试平台的任务优先级：**价值 = 资产重要性 × 成功概率 ÷ 成本**。
> 力气花在对的地方——方向错了，成功率再高也是负资产。

## 定位

`valuesched` 是 `agent/planner` 之上的**资产级排序层**：

- planner 决定「一个任务里怎么打」（任务内意图规划）；
- valuesched 决定「今天先打哪个资产」——给每个 (资产 × CVE × EXP) 候选打分，
  产出优先级队列，调度循环每天取 Top N 下发（艾维利工作法内建进调度：
  每天只做最重要的 N 件）。

**放置理由（独立顶层包而非 server 内聚模块）**：打分与排序是纯计算，无
HTTP/DB 依赖（仅标准库）；server → valuesched 单向依赖不引入环；无需
Postgres 即可全量测试（server/db 包测试依赖 DSN，缺失时会 skip）；与
guard/evidence/enrich 等聚焦职责的顶层包布局一致；对现有调度/任务代码
零侵入（只新增，不改）。

## 公式

```
score = asset_value × P(success) ÷ cost

asset_value = 基础价值(tier) × 控制平面距离系数
P(success)  = P(指纹正确) × P(EXP可用) × P(前置满足)
cost        = 原子操作数(min 1) × 模型预算系数
```

归一化：`score(0-100) = clamp(raw ÷ 8.0 × 100, 0, 100)`，两位小数。
理论满分基准 8.0 = S 层基础价值 4.0 × 控制平面最大系数 2.0 × P=1 ÷ 最小
成本 1.0。采用**绝对归一化**（不按批次相对归一），分数跨天可比、可解释。

## 因子定义

### asset_value：资产重要性

**基础价值**：优先取显式覆盖 `BaseValueOverride`（>0 时生效，如按 kt-vuln
的 score 0-100 换算），否则按价值分层 tier 映射（与 kt-vuln 资产目录取值
对齐，见 `server/vuln_tools.go`），未识别/缺省 1.0：

| tier | S | A | B | C | D | E | exclude | 未知/空 |
|------|---|---|---|---|---|---|---------|--------|
| 基础价值 | 4.0 | 3.0 | 2.0 | 1.5 | 1.0 | 0.5 | 0 | 1.0 |

**控制平面距离系数**（与最近控制平面资产的图距离 `ControlPlaneHops`，
指针 nil = 无图信息）：

| 图距离 | nil（无图信息） | 0 跳（自身即控制平面） | 1 跳 | 2 跳 | ≥3 跳 |
|--------|----------------|----------------------|------|------|-------|
| 系数 | 1.0 | 2.0 | 2.0 | 1.5 | 1.0 |

任务口径为 1 跳 ×2、2 跳 ×1.5、无图信息 1.0；0 跳（自身即控制平面）与
1 跳同档 ×2，≥3 跳衰减回基线 1.0 是补齐档。**注意 nil 与 0 的区别**：
字段是指针，零值（nil）= 无图信息，绝不误加成 ×2。

### P(success)：成功概率

| 因子 | 输入 | 缺省（nil/未知） | 越界处理 |
|------|------|----------------|----------|
| P(指纹正确) | 资产指纹 vs CVE affected 范围匹配度，0-1 | 0.5 | 钳制到 [0,1] |
| P(EXP可用) | EXP 历史命中率，0-1；无历史默认 0.5 | 0.5 | 钳制到 [0,1] |
| P(前置满足) | 三态布尔：true→1.0，false→0.3，nil（未验证）→0.5 | 0.5 | — |

### cost：成本

- `AtomicOps`：预估原子操作数，`<1` 钳制为 1；
- `ModelBudgetFactor`：模型预算系数，确定性收割 1.0（`ModelBudgetDeterministic`），
  需 LLM 猎杀 3.0（`ModelBudgetLLMHunt`）；`<=0`/缺省 → 1.0（同时是除零防御）。

### 优先级分档

| 分档 | P0 | P1 | P2 | P3 | P4 |
|------|----|----|----|----|----|
| 分数 | ≥80 | ≥60 | ≥40 | ≥20 | <20 |
| 含义 | 立即执行 | 优先执行 | 正常排入 | 靠后 | 垫底/暂缓 |

## 优先级队列规则

- **去重**：同一 `AssetID + CVE` 只保留最高分的 EXP（同分保留先输入的，
  输入顺序即调用方给出的 EXP 优先序）；
- **排序确定性**（避免同分候选日间抖动）：分数 ↓ → P(success) ↓ →
  成本 ↑ → (AssetID, CVE, ExpID) 字典序 ↑；打乱输入顺序结果不变；
- `SelectTopN(candidates, n)`：Rank 后截取前 n 条；`n<=0` 返回 nil
  （今日不派任务）；n 超过队列长度返回全量。

## API

```go
valuesched.Score(c Candidate) Scored        // 单候选打分（含完整分解）
valuesched.Rank(candidates) []Scored        // 去重 + 排序的完整队列
valuesched.SelectTopN(candidates, n) []Scored // 每日 Top N 入口
(s Scored).Explain() string                 // 单行中文因子链（任务快照留痕）
valuesched.Ptr(0.9)                         // 构造可选因子指针
```

`Scored` 内嵌 `Candidate`（原样带回）+ `Breakdown`（每个因子的生效值：
`BaseValue` / `HopsToControlPlane` / `ControlPlaneFactor` / `AssetValue` /
`PFingerprint` / `PExp` / `PPrereq` / `PSuccess` / `EffectiveOps` /
`EffectiveModelBudget` / `Cost` / `RawScore` / `Score` / `Priority`），
字段全带 JSON tag，可直接序列化进任务快照。分解侧 cost 字段用
`Effective*` 前缀（钳定后生效值），与输入同名字段区分，避免嵌入后
选择器/JSON 歧义。

## 示例计算

### 例 1：S 层、控制平面 1 跳、成熟 EXP、LLM 猎杀

```
输入：tier=S, hops=1, 指纹匹配=0.9, EXP命中率=0.8, 前置满足=true,
     原子操作=2, 模型预算=LLM猎杀(3.0)

asset_value = 4.0 × 2.0                    = 8.0
P(success)  = 0.9 × 0.8 × 1.0              = 0.72
cost        = 2 × 3.0                      = 6.0
raw         = 8.0 × 0.72 ÷ 6.0             = 0.96
score       = 0.96 ÷ 8.0 × 100             = 12.00（P4）

Explain(): 资产#101 CVE-2023-46604 exp-atomic：12.0分(P4) = 资产价值8[基础4×控制平面2(1跳)] × P(成功)0.72[指纹0.9×EXP0.8×前置1] ÷ 成本6[2操作×系数3]
```

### 例 2：全部 unknown（零值候选走缺省）

```
asset_value = 1.0 × 1.0                    = 1.0
P(success)  = 0.5 × 0.5 × 0.5              = 0.125
cost        = 1 × 1.0                      = 1.0
raw         = 0.125
score       = 1.56（P4）
```

### 例 3：确定性收割的高价值靶（P0 形态）

```
tier=S, hops=1, 指纹=1.0, EXP=0.9, 前置=true, 原子操作=1, 确定性收割
asset_value=8.0, P(success)=0.9, cost=1.0
raw=7.2 → score=90.00（P0）
```

## 集成点

本包只做打分与排序，不接任务系统（按任务要求留集成点，不改现有调度代码）：

1. **候选组装**（调用方负责）：
   - 资产维度：kt-vuln 资产目录（唯一事实源，`vuln_search_assets` /
     `VULN_SVC_API_URL /api/assets`）——tier/score 填 `Tier`/
     `BaseValueOverride`；用 `cve=<CVE>` 过滤受影响资产，verdict
     （executable > vulnerable）可换算 `FingerprintConfidence`；
   - EXP 维度：调用方自持的 EXP 元数据（命中率→`ExpMaturity`，前置
     布尔→`PrereqMet`，预估操作数→`AtomicOps`，是否需 LLM 猎杀→
     `ModelBudgetFactor`）；
   - 每个候选的三个 id（AssetID/CVE/ExpID）只用于去重与追溯，不查库。
2. **每日调度循环**：调 `SelectTopN(candidates, N)` 取今日 Top N，逐条
   下发为任务；`Breakdown`/`Explain()` 随任务留痕，回答「为什么今天先打它」。
3. **任务下发**：可配合 P3 的 vuln 资产工作集接口把选中资产的快照钉到
   任务上——`POST /api/tasks/{id}/vuln-workset`（`server/task_vuln_worksets.go`，
   items[].snapshot 即资产快照，Breakdown 可一并放入 snapshot JSON）。
4. **控制平面图距离**：当前 `db/` 资产关系是隐式列（domain/ip/
   bound_domains/root_domain 等），无显式资产图边表、也无「控制平面」
   标记；接口已留——`Candidate.ControlPlaneHops *int`，传 nil 即无图
   信息（系数 1.0）。未来有图数据（如 kt-vuln 侧控制平面标注或本地
   资产图）只需在组装候选时算好跳数填入，无需改本包。

## 测试

`valuesched/score_test.go` / `valuesched/queue_test.go`：表格驱动，覆盖
因子分解正确性（含边界：除零防御、空输入、全部 unknown、概率越界、
ops/系数钳制、归一化封顶）、控制平面系数各档、去重（含同分保留先输入）、
Top N 截断（n<=0/负/超长）、同分 tie-break 确定性、输入顺序无关性、
可解释性输出片段。纯逻辑测试，不需要数据库：

```
go test ./valuesched/
```

## 遗留问题

- 控制平面图距离暂无数据源（见集成点 4），当前所有候选系数均为 1.0，
  分层差异只来自 tier；
- tier → 基础价值映射（S=4.0 … E=0.5）与理论满分基准 8.0 是初版经验值，
  未用历史命中率回归校准；建议积累一批任务执行数据后复核分档阈值
  （P0-P4 的 80/60/40/20）与映射比例；
- EXP 元数据（命中率/前置/操作数）尚无落库来源，首个集成方需自带；
  后续可把 `Breakdown` 回写为 EXP 命中率的滚动统计闭环。
