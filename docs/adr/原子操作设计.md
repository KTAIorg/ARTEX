# 原子操作设计

> 状态：第一块地基（已落地）。对应任务：把「确定性动作」从 LLM 循环里拆出来。
> 代码：`atomic/`（注册体系 + 示范操作）、`server/atomic_tools.go`（接入）。
> （本页按宿主 hook 约定放在 `docs/adr/`——它是新子系统的架构决策记录。）

## 1. 定位与背景

ARTEX 是 AI 自主渗透测试系统：agent 用 LLM 规划，工具执行。历史上「确定性动作」（探测指纹、验证弱口令、执行 PoC）也混在 LLM 循环里跑，任何一次执行偏差都会吃掉前面所有环节的成功率。成功率先验公式：

```
P(拿下) = P(指纹正确) × P(EXP可用) × P(前置满足) × P(执行无误)
```

原子操作层修的是 **P(执行无误)**：

- 每个原子操作 = `key` + 描述 + JSON Schema（typed input/output）+ 幂等执行函数；
- **循环里不放 LLM**——同样的输入必然得到同样结构的输出，便宜模型与无限制模型只负责决策与武器编写（选哪个操作、写什么 payload/正则）；
- 每次执行自带 `evidence` 留痕，这是合规平台的审计底线。

合规语境：这些是**授权渗透测试平台**的确定性工具，只能用于 engagement 授权范围内的目标。操作本身不做越权判断——授权边界由上层任务/资产 scoping 管，与 Bash/自定义工具同一信任模型（平台侧可信、目标侧受授权约束）。

## 2. 输出契约（envelope）

所有原子操作的输出是统一的 `Result` envelope（`atomic/atomic.go`）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `ok` | bool | 动作是否成立（命中/验证通过/凭据有效） |
| `evidence` | string | 可留痕的输出片段——一句话能进报告/审计日志的判定依据 |
| `error` | string | 执行层失败原因（不可达/参数非法），成功时为空 |
| `data` | object | 操作自身的结构化字段，由各操作 `OutputSchema` 描述 |
| `duration_ms` | int | 执行耗时，由 `Execute` 统一注入 |

关键设计：**三态契约**，把「结论为否」和「执行失败」分开——

- 命中/成立：`ok=true`，`error=""`；
- 结论为否（如弱口令字典试尽未命中）：`ok=false`，`error=""`，evidence 说明试了几次；
- 执行失败（目标不可达、参数非法、正则编译不过）：`ok=false`，`error!=""`。

`Execute` 是唯一推荐入口，它在边界上封死契约：未注册 key 返回错误 Result（不 panic）；Run 内部 panic 被恢复为 `ok=false`；`evidence` 为空时兜底补齐；统一计时。

## 3. 注册方式

```go
// atomic/<你的操作>.go
func init() {
    err := atomic.Register(atomic.Op{
        Key:          "atomic_xxx",           // 小写字母开头 + 小写字母/数字/下划线，3-64 字符
        Description:  "给模型看的描述（含输出契约说明）",
        InputSchema:  objSchema(map[string]any{ ... }, "必填参数"),
        OutputSchema: atomic.OutputSchema(map[string]any{ /* data 字段 */ }),
        Run:          func(ctx context.Context, in json.RawMessage) atomic.Result { ... },
    })
    if err != nil { panic(err) } // 注册期失败要在启动/测试期炸出来
}
```

注册表进程内全局（`init()` 注册、不可变），`atomic.List()` 按 key 排序返回全量。`server/atomic_tools.go` 把注册表整体转成 `actool.CoreTool`，经 `hostTools()` 注入——**新操作只要写文件 + init 注册，agent 侧零接线**。

## 4. 三个示范操作

| key | 修哪一环 | 说明 |
|---|---|---|
| `atomic_fingerprint` | P(指纹正确) 的数据采集 | 纯标准库 HTTP 指纹：根路径状态码、Server/X-Powered-By、`<title>`、常见路径（/robots.txt /login /admin）回包；不跟随重定向（3xx 本身是指纹要素）；scheme 自动猜测（443 先 https）。 |
| `atomic_weak_cred` | P(前置满足) | 小字典弱口令核验：内置用户名 6 × 口令 12（均 <20，调用方可覆盖但限量）。支持 `http_basic`（判定 = 非 401/403）与 `ssh`（x/crypto/ssh 密码认证，仓库既有依赖）。内置单次超时（默认 5s）、尝试间隔限速（默认 200ms）、总次数上限（默认 24、硬上限 64）。 |
| `atomic_verify_poc` | P(执行无误)（EXP 执行器雏形） | HTTP 请求模板（method/url/headers/body，支持 `{name}` 占位符）+ 成功判定正则 `match_re`，确定性执行一次并判定；可选 `expect_status` 精确校验、`auth_user/auth_pass` 自动 Basic 认证。 |

弱口令语义边界（刻意）：`http_basic` 的判定是「凭据被接受」。对永远回 200 的开放端点会命中任何凭据——调用方应先 `atomic_fingerprint` 确认目标确有 401 质询再下结论。垂直切片（见 §7）就是这个用法。

## 5. 与 customtool 的关系

两条通道、一张表、一个注入点：

| | customtool（`server/customtool.go`） | 原子操作（`atomic/`） |
|---|---|---|
| 执行体 | tools 表里的数据规格（command/script/http 的 exec JSON），运行时渲染分派 | Go 代码（确定性、类型化契约） |
| tools 行 | `system=false`，kind=command/script/http | `system=true`，kind=builtin（沿用 SeedTool 默认） |
| 可编辑性 | 全量可编辑（用户自建） | key/handler 只读；描述/schema/绑定/开关可在工具页覆盖 |
| 注入 | `hostTools()` → customTools() | `hostTools()` → atomicTools() |

**为什么不新增 kind**：customtool 的 `kind` 语义是「数据驱动 exec 规格」的分派字段，`exec` 列存的是规格本体；原子操作的执行体在代码里，`exec` 列对它没有意义。走 builtin 通道（vuln/orchestration 工具同款）零 schema 迁移、零新分支，且自动获得 SeedTool 首插入幂等 + 工具页管理 + ToolResolve 按 agent 绑定过滤的全部既有行为。**不破坏现有 command/script/http 工具**：两条通道在 `hostTools()` 汇合后互不感知。

绑定：`seedAtomicTools()` 默认绑 `worker` + `pentest`（动手执行的两个 agent；planner 只规划不该执行）。管理员可在工具页改绑/关停。

## 6. 如何加一个新原子操作

1. 新建 `atomic/<name>.go`，`init()` 里 `Register`（模板见 §3）；
2. 实现必须是幂等确定性函数，输出走 `OK(...)` / `Failf(...)` / 三态（结论为否用 `Result{OK:false, Evidence:...}`）；
3. 主动探测类动作沿用内置约束惯例：单次超时、间隔限速、次数/大小上限（参考 `weakcred.go` 的 clamp 系）；
4. 测试写进 `atomic/atomic_test.go`（httptest mock 目标），无 LLM、无 DB、无外网；
5. 完事。seed（`seedAtomicTools`）与注入（`atomicTools`）遍历注册表，不需要再接线。

约束：Go 标准库 + 仓库既有依赖；不引入新第三方库；注释中文并说明授权语境。

## 7. 无 LLM 垂直切片（验收测试）

`atomic/atomic_test.go` 的 `TestVerticalSliceNoLLM`：本地 mock 靶场（httptest）上，三步只经 `atomic.Execute` 串联，全程无 LLM/DB/外网：

```
atomic_fingerprint(host:port)          → 确认活着的管理台，取 host/port（data 回传）
atomic_weak_cred(http_basic /admin)    → 内置字典命中 admin/admin123
atomic_verify_poc(带凭据 GET /admin + 正则) → 命中旗标 flag{atomic-ok}
```

另有反向核对（错误凭据下同一 PoC 必须「未命中」而非误报）与 SSH 弱口令（进程内 x/crypto/ssh 最小服务端）用例。服务端接线由 `server/atomic_tools_test.go` 验证：CoreTool 封包不丢 envelope 契约、tools 表 seed 落库且默认绑定正确。

## 8. 遗留与下一步

- **通用 EXP 执行器**：`atomic_verify_poc` 只覆盖 HTTP 判定；后续需要多步 PoC（先写后读、带编码链）与 TCP 原始协议版。
- **结果缓存/去重**：同一目标同一操作的重复执行可在任务级缓存（幂等性已保证正确，缓存只为省时省流量）。
- **evidence 入库**：目前 evidence 随工具结果回到会话；应与 finding/evidence store 打通直接留痕。
- **限速全局化**：delay/上限目前是操作内局部约束；跨操作对同一目标的总速率约束（不打断授权测试语义的前提下）待做。
- **Telnet/FTP 等协议**：刻意未做（现代目标占比低、明文协议判定易误报），需要时按 §6 扩展。
