# 靶场回归与复利指标

> 状态：已落地（Wave1 后续：EXP 资产库的质量闸门与 KPI 面）。
> 代码：`range/`（目录名 range、包名 vrange，见 §2）、`db/exp_metrics.go`、
> `server/exp_library.go`（闸门接线）。
> （本页按宿主 hook 约定放在 `docs/adr/`——它是新子系统的架构决策记录。）

## 1. 定位与背景：复利为什么会是假的

EXP 资产库（`db/exp_assets.go`）的复利故事是：成功利用沉淀为参数化 EXP，
agent 猎杀一次、全平台永久收割同类目标。这个故事的隐含前提是
**库里的 EXP 真能打下来**。现实里至少三种漂移会让它静默失效：

- 上游组件升级（路径改版、判据变化、行为收紧）；
- EXP 作者当时的目标有特殊前提（前置条件未显式化）；
- success_oracle 写得过松（打到任意 200 页面就自称成功）或过紧
  （真命中了却判为失败）。

没有靶场回归，这些失效只能在真实目标上被发现——agent 碰一鼻子灰、
失败沉淀进台账、命中率统计慢慢腐烂，**复利是假的**。所以本页的决策是：
EXP 入库（或更新）前必须在受控靶标上真的打一遍，至少一个靶标 Pass
才放行；同时把「复利率」做成一等指标持续度量。

成功率先验公式里，这一层守的是 **P(EXP可用)** 的入库面（`ExpAssetStats`
命中率是它的实然测量面）。

## 2. 包放置决策：`range/` 目录、`vrange` 包名

- 目录按任务口径叫 `range/`，但 `range` 是 Go 关键字、不能作包名，
  故包名为 **vrange**（vuln range）。导入方写
  `import vrange "github.com/Autumn-27/artex/range"`。
- 不放 `db/`：靶场是执行层关注点（起 HTTP 服务、跑请求模板），不是持久化；
  db 反而被它依赖（`ExpAsset` 类型 + 指纹匹配器 `db/exp_match.go`），
  放 db 会造成分层倒挂。
- 不放 `server/`：闸门是纯 Go 逻辑（httptest 靶标、无 PG、无 HTTP 路由），
  server 只在写路径上调用它；独立成包让它与 `atomic/` 同级——都是
  「确定性执行层」。

## 3. 靶标模型（`VulnTarget`）

一个靶标 = 受控环境里的一份「带已知漏洞/特征的模拟资产」，声明两件
质量闸门关心的事：

| 字段 | 语义 |
|---|---|
| `Name / Component / Version` | 靶标标识与指纹维度（与 EXP 指纹条件的 `components.name` / `version_range` 对齐） |
| `Launch` | 启动方式：`builtin-httptest`（内置纯 Go）｜`docker`（未来扩展） |
| `Fingerprint` | **预期 EXP 应命中的指纹**：靶标作为资产的指纹 JSON（`db.AssetFingerprint` 形态），正确 EXP 的 `fingerprint_match` 必须命中它 |
| `SuccessOracle` | **预期成功判据**：靶标侧 ground truth（`status_codes`/`keywords`/`regex`，与 `success_oracle` 同构），正确 EXP 打出来的响应必须满足 |

三个内置靶标（全部 httptest、进程内自起、仅回环流量、无 docker 无外网），
各覆盖一个原子操作（`atomic/`）的验证路径：

| 靶标 | 模拟漏洞 | 覆盖的验证路径 |
|---|---|---|
| `weakcred-basic-auth` | `/admin/` 由 admin/admin123 保护，匿名 401、正确凭据 200+FLAG | `atomic_weak_cred`（弱口令可用 = 凭据被接受且拿到受保护内容） |
| `cve-known-path-echo` | `/vuln/echo` 回显 msg 并附 CVE 水印，其余 404 | `atomic_verify_poc`（知道漏洞路径 + 判据捕获回显） |
| `version-banner-gate` | 根路径横幅携带 MiniProxy 0.9.7，其余 403 | `atomic_fingerprint`（版本区间覆盖靶标版本才命中） |

靶标定义不可变、可重复 `Start()`，每次返回独立 `TargetInstance`
（`BaseURL` 注入 EXP 模板的 `{target}` 占位符）。

## 4. 回归执行器（`RunRegression`）

对每个 (EXP × 靶标) 组合执行四步，输出 `Pass/Fail + 耗时 + evidence`：

1. **指纹匹配**：EXP 的 `fingerprint_match` 命中靶标资产指纹
   （复用 `db.MatchExpFingerprint`；运行实例 URL 会合并进资产指纹，
   EXP 的 `paths` 维度条件因此可用）。不命中 → 该组合记
   `fingerprint_mismatch` / `version_mismatch`，**不计 EXP 的罪状**
   （EXP 本来就只服务特定指纹面），也不执行。
2. **模板执行**：渲染并执行 `exec_template`（kind=http；`{target}` = 靶标
   基地址；渲染后残留占位符 = 参数缺口，直接判执行失败）。
3. **EXP 判据**：EXP 自己的 `success_oracle` 对响应求值。
4. **靶标判据**：靶标 ground-truth oracle 对同一响应求值。

`Pass = 指纹命中 ∧ 执行无错 ∧ EXP 判据命中 ∧ 靶标判据命中`。
第 3、4 步构成**双 oracle**，拦两种判据漂移：

- EXP 判据未中、靶标判据中 → 判据写错（漏报真命中）；
- EXP 判据中、靶标判据未中 → 判据过松（打到任意页面自称成功，误报）。

两种漂移都会让命中率统计失真，闸门都要拦。

**为什么直接执行 HTTP 模板而不是包一层 `atomic.Execute("atomic_verify_poc")`**：
闸门需要原始响应（状态码 + 响应体全文）分别喂两个 oracle，而
`atomic_verify_poc` 只回命中片段；把 oracle 塞进 `match_re` 在多状态码 /
关键字 AND 语义上有损。占位符渲染语义与 atomic 的 `vpRender` 保持一致。

oracle 求值语义（EXP 侧与靶标侧同一套）：声明维度之间 AND——
`status_codes` 含状态码；`keywords` 全部子串出现；`regex` Go 语法命中。
刻意从严：宁可误杀判据含糊的 EXP，不放判据过松的。

## 5. 入库闸门（`ValidateExpAgainstRange` + `WithRangeGate()`）

```
ValidateExpAgainstRange(ctx, exp) → GateResult{Allowed, Reason, PassedTargets, Report}
Allowed = 至少一个内置靶标 Pass
```

拒绝原因分层（修复方向不同）：

- 一个靶标指纹都没命中 → 指纹面与靶场对不上（指纹条件写歪或太窄）；
- 命中了却全部打不下来 → 执行模板/成功判据有误（逐靶标列出失败原因）。

接线在 `server/exp_library.go`：`Create/Update` 的**可选参数**
`WithRangeGate()`（variadic，既有调用零改动、既有测试不受影响）。
闸门在语义校验之后、持久化之前执行；PG 未初始化时写路径返回可读错误
而非 nil 解引用。刻意做成可选而非无条件强制：存量 EXP 与 command/script
类 EXP 尚无对应靶标，一刀切会把库锁死；新登记/迭代 http 类 EXP 时应默认带上。

## 6. 复利指标（`CompoundMetrics`）

数据源就是 `exp_attempts` 台账（`db/exp_metrics.go`，由 `ExpAssetStats`
的查询面扩展），输出结构化 JSON 供 web 看板：

| 字段 | 口径 |
|---|---|
| `compound_rate` 复利率 | `exp_success / total_success`：分子 = 窗口内台账 success 行（经 EXP 库完成）；分母 = 平台全部成功拿下数 |
| `exp_hit_rate` EXP 命中率 | `exp_success / total_attempts`（P(EXP可用) 的窗口化实然测量） |
| `total_attempts / exp_success / total_success` | 窗口计数 |
| `top_failure_reasons` | 失败原因分布 Top 5（喂匹配修正：如 `version_mismatch` 扎堆 → 对应 EXP 版本区间该收紧） |
| `trend` | 按天趋势数组（date / attempts / success / hit_rate） |

**复利率分母的刻意取舍**：台账只覆盖 EXP 库路径，单看 `exp_attempts`
时分母退化 = 分子（率恒为 1）。不做隐性猜测——`SetTotalSuccess(n)`
是显式接线点：接平台 findings（拿下）口径后注入真实分母，复利率才有
区分度。默认窗口 30 天（`since` 传零值）。

## 7. 测试

- `range/regress_test.go`：三场景——全 Pass / 有 Fail（错口令，执行成功
  但双判据不中）/ oracle 不匹配（判据写错与判据过松两个方向）+ 跨靶标
  矩阵 + 版本区间不命中 + 非 http 模板拒执行。
- `range/gate_test.go`：Pass 放行、Fail 拒绝（含指纹面/判据分层原因）。
- `db/exp_metrics_test.go`：真库测试（无 PG 自动 skip）——已知分布灌台账，
  校验复利率/命中率/top 失败原因/按天趋势 + `SetTotalSuccess` 数学 +
  空窗口零值 + JSON 字段齐全。
- `server/exp_range_gate_test.go`：闸门接线（拒绝路径纯逻辑可跑；放行
  路径端到端真库，无 PG skip）。

运行：`go test ./range/ ./db/ ./server/`（无 PG 自动 skip）；
带库：`ARTEX_PG_DSN=... go test ./db/ ./server/`。

## 8. 遗留问题

- **command/script 类 EXP 无靶场**：闸门当前只支持 `kind=http`；docker 级
  靶标（`Launch: docker`）留待后续——VulnTarget 的 `Launch`/`Start` 已
  为其留了扩展点。
- **复利率分母未接 findings 口径**：`SetTotalSuccess` 接线点已备，等看板
  落地时从 findings 表取数注入。
- **闸门未默认强制**：`WithRangeGate()` 按需启用；等存量 EXP 补齐靶标、
  command/script 靶场就绪后，可升级为默认强制（写路径删掉可选项即可）。
- **web 看板未接**：`CompoundMetrics` 与 `Report` 都是可直出 JSON 的
  结构，HTTP 端点与前端留待看板任务。
